# Privacy

## Current behavior

Everything below is read locally, only while the app is open, and is never stored or sent anywhere. The System page reads aggregate CPU, memory, swap, memory pressure, battery and the macOS thermal state, and network and startup-disk byte rates, while Kleari is open to look at (its window visible, or its menu-bar panel open): every second while System is on screen and every 5 seconds otherwise (pause stops it), so System and the Dashboard open with recent readings. Nothing is read while both are out of sight. It also reads: hardware and macOS details (model identifier, chip, core counts, memory size, display name and size, startup-volume name and size, boot time, battery cycle count and capacity). It lists launch agents and daemons from `~/Library/LaunchAgents`, `/Library/LaunchAgents` and `/Library/LaunchDaemons` by reading each plist's label and program path; only the label, a display name (the app the program belongs to) and whether the program still exists are sent to the interface. Program paths are used for that check and dropped, never sent, stored or logged. The check is skipped for programs on network volumes, so it never contacts another computer. The readings are kept in memory for the charts while the app is open, and never stored. The Storage page reads the startup disk's capacity, the size of the swap and sleep-image files, and whether Full Disk Access is on (by opening, never listing, `~/Library/Mail`, `Safari` and `Messages`). When you choose Analyze, it reads the names, sizes and modification times of files in fixed locations (Applications, your home folder, and the system folders), read only. The only contents it opens are installed apps' `Info.plist` files, for their names and bundle identifiers, so each app's data can be counted with it. It opens no other file contents, follows no symbolic links, stays on the startup disk and doesn't list cloud folders. macOS may ask before Kleari can read some of your folders. The interface receives folder sizes with folder names, the largest items in each category, and the names and folders of files of 1 GB or more, shown only on screen. The result is kept in memory while the app is open and never stored, logged or sent. The backend also has a process summary (names, PIDs, CPU and memory, with app grouping that reads each executable path once and discards it) and a scan of a folder you pick in the macOS folder panel. No screen uses either today. When you choose Scan, the Developer page reads the names and sizes of known developer caches (npm, Homebrew, Xcode and others) and of build folders in projects it finds in your home folder and any folder you add in the macOS folder panel. To find projects it reads folder listings, and for each Git repository the last line of `.git/logs/HEAD` for the time of the last commit; it also reads Xcode's and npm's version files. It opens no other file contents and doesn't follow symbolic links. If Docker is running, it asks Docker's own engine, on this Mac, how much space images, build cache, volumes and containers use; otherwise it reads only the size of Docker's disk image. Project names, folder names and locations are shown on screen only; the scan is kept in memory while the app is open, and the folders you add are forgotten when it quits. For the Processes page, Kleari reads, while it is open to look at (as for System: every 2 seconds while Processes is on screen and every 5 seconds otherwise, so the page opens with a recent list): each process's name, PID, owner account, start time, CPU time, memory, thread count where macOS allows, and executable path. For processes of root and other accounts, which macOS doesn't report to apps directly, the memory, CPU time and owner come from Apple's own `ps` tool, run read-only with fixed arguments. The executable path and app bundle are shown as the process's location, on screen only; nothing is stored, logged or sent, and the latest list is kept in memory only while Kleari runs. Its Quit button asks a regular app to quit, the same as its own Quit menu item, after you confirm; the request and whether macOS delivered it are recorded in Kleari's local history with the app's name (not its path). When you choose a Cleanup scan, Kleari reads the names, sizes and dates of items in `~/Library/Caches`, `~/Library/Logs`, your temporary folder, known package caches, Xcode's and the Simulator's folders, your projects' `node_modules` (and whether a lockfile is next to it), and, for a Deep scan, the files in folders you granted or added. It also reads which apps are running, by bundle identifier, and a simulator's `device.plist` for its name. It opens no other file contents. Downloads, Desktop, Documents and Movies are read only after you choose Grant access, and your answer is remembered. The review is kept in memory while the app is open. When you approve a preview, the items move into `~/Library/Application Support/dev.bakare.kleari/Quarantine` on this Mac. Kleari keeps a local history in `history.sqlite3` in the same folder, readable only by your account: each quarantined item's name, category, size, identity and original path (needed to put it back), and for a build folder from a folder you added outside your home folder, that added folder's path (so Quarantine can ask you to choose it again before restoring), what became of it, and your answers to folder-access requests. It also keeps the activity log shown on the Activity page: for each Cleanup scan, Storage analysis, Developer scan, item sent to review, move, restore, permanent delete, folder-access answer and quit request, the time, counts, sizes and outcome, the scan mode, folder or app name it concerned (never a path), and which quarantined items it involved, shown with their folder as `~/…` (or only the folder's name outside your home folder). Activity older than the period you choose in Settings (90 days by default) is deleted, and Clear log deletes it all. Your Settings choices and the folders you exclude from scans (their paths) are kept there too. Notifications you turn on are shown by macOS on this Mac. Nothing is sent anywhere, and Kleari never empties quarantine on its own; items stay until you restore or permanently delete them. The menu-bar popover, while it is open, reads the same live readings, hardware details and startup-disk capacity as the Dashboard (activity every second), the last Cleanup scan's findings, what quarantine holds and the activity log, all from this Mac, and shows them on screen only; it reads nothing while it is closed, stores nothing of its own and starts no scan. Uninstall (Settings › About) moves Kleari's own folders and settings (in `~/Library`: Application Support, Caches, WebKit, HTTPStorages, Saved Application State and Preferences, each only for `dev.bakare.kleari`) and the installed app to the Trash, after trying to turn off Open at login (if macOS keeps it on, the result says so and where to remove it). It runs only when quarantine is empty and never touches your files. The appearance preference (System, Light or Dark) is kept in the app's WebView storage. A scheduled scan (Settings › Scanning, off by default) is the same read-only Cleanup scan, run by Kleari at the time you chose while it is running; it is recorded in Activity and notifies what it found, and moves nothing. The Mouse module (off by default, and only once you allow Kleari under Privacy & Security › Accessibility) sees mouse wheel and extra-button events as they happen, to change them, and left or right clicks each only while one of your combinations uses that click (if you change which clicks they use, or turn them off, while holding a mouse button, the change waits until you let go, at most 10 seconds: until then a change of combinations leaves the previous settings working, and turning off passes new presses on untouched while finishing the presses it had already intercepted, dropping their release without doing their action); it never sees keystrokes or pointer movement, and nothing it sees is stored, logged or sent. Its settings, including any keyboard shortcut you record for a button, are kept in the history file. While the Mouse page is open, its button finder is told which mouse button you press and how the wheel scrolls inside Kleari's own window (no permission needed, no keystrokes), only to light up the drawn mouse; only which buttons it has seen is kept, in the app's WebView storage, so the page can point out settings your mouse can't trigger. The Storage page's Browse view, when you open a folder, reads the names, sizes and dates of what is in it (folders measured through everything inside), in your home folder only; folders you excluded in Settings are listed by name and never entered. Results are shown on screen and kept in memory while the app is open; what you send to review moves only into quarantine when you approve it. On the Files page, each tool runs only when you choose Search, on your home folder (not your Library, the Trash, app packages or folders you excluded): Large & Old reads names, sizes and dates; Duplicates also reads the contents of files of the same size, only to compute SHA-256 hashes that are compared and never stored; Similar Images has macOS decode up to 20,000 pictures into tiny 9×8 grayscale thumbnails, compared and never stored; Downloads reads, for what is in Downloads, the name of the app macOS recorded as downloading it (never the address); AI clutter reads names and sizes in the folders AI tools use. Results are shown on screen and kept in memory while the app is open. When you choose Scan on the Apps page, Kleari reads the app bundles in `/Applications`, `/Applications/Utilities` and `~/Applications` (each one's `Info.plist`, for its name, bundle identifier and version, and its size), which apps are running, and the names, sizes and dates of entries directly in the Library folders apps keep data in (Application Support, Caches, Preferences, Saved Application State, Containers, Group Containers, HTTPStorages, WebKit, Logs, Cookies, Application Scripts and LaunchAgents), and of installer files directly in Downloads and on the Desktop. It opens no other file contents and follows no symbolic links. The results are shown on screen only and kept in memory while the app is open. Removing an app, after you confirm, moves it to the Trash through macOS and records its name in Activity; what it kept in your Library, and any leftovers or installers you send, go to Cleanup's review and move only into quarantine when you approve them. Kleari's only internet request is the update check: at launch (unless Settings › About › Check for updates automatically is off) and when you choose Check now, it downloads `latest.json` from Kleari's GitHub releases (the latest stable release's, or with Settings › About › Beta updates on, the `beta-channel` release's, which names the newest beta or stable version), and the update itself only when you choose Install. It sends nothing about this Mac or your files beyond what any download sends (your IP address and a user agent). There is no telemetry, account, hosted backend or AI, so Kleari doesn't know who uses it: the only download figures are GitHub's public counts of each release file. This is a statement about current code, not the future product.

## Product requirements

- Local-first operation; no mandatory account or hosted backend.
- No telemetry by default and no default file-content upload.
- Scans, settings and history are local. Request narrow user authorization only when a future feature needs it.
- Minimize storage of full paths and sensitive metadata. Redact diagnostics; never log credentials or file contents.
- Keep deterministic functionality authoritative and usable offline.
- Optional AI requires explicit provider selection and consent, clear disclosure of exactly what data is sent, minimization, and provider-specific retention disclosure. AI cannot authorize operations.

## Retention and public release

Quarantine is never emptied automatically (product decision, shown as "Always on" in the design); there is no retention period or size cap, and items use disk space until you delete them. History retention and export are unresolved. Never silently delete to enforce retention. Before public release, publish accurate privacy disclosures covering permissions, local database/history, diagnostics, optional provider data flows, retention and uninstall behavior. See [release checklist](release-checklist.md).
