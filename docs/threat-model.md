# Threat model

**Scope:** Kleari, a local macOS app. Its file-changing operations are Cleanup's moves into quarantine, Quarantine's restores and its separately confirmed permanent deletes ([ADR-012](adr/ADR-012-cleanup-and-quarantine.md)); Processes can ask a regular app to quit ([ADR-009](adr/ADR-009-process-quit.md)); the Mouse module changes mouse input once allowed ([ADR-016](adr/ADR-016-mouse-module.md)); Uninstall moves Kleari's own folders to the Trash. Persistence is the local SQLite history (owner-only) and the WebView's storage for small interface choices. Each row below says what is implemented; where it says "required", that part is not yet built.

## How Kleari is protected, in short

Kleari holds a lot of local data (file names, sizes, paths in quarantine records) and broad grants (Accessibility, folder access, possibly Full Disk Access), so the design keeps every way in narrow:

1. **The network.** No server and no listening port. The only outbound request is the update check: fixed HTTPS manifests of Kleari's own GitHub releases (stable, or with Beta updates on, the rolling `beta-channel` manifest), and downloads only from Kleari's own release assets. Nothing about the Mac is sent. Updates install only after the user chooses, only with a valid signature from Kleari's built-in key that names the announced version (`requireSignedVersion`), and never during a quarantine operation. A tampered manifest, mirror, DNS or proxy can at most withhold an update.
2. **The interface.** The WebView loads only Kleari's bundled code (CSP `script-src 'self'`, no remote content), so injected text (file names, plist labels, Docker output) is shown as text, never run. Each window has its own Tauri capability with only the commands it needs.
3. **Commands.** Every IPC input is validated in Rust (closed enums, `deny_unknown_fields`, bounded lengths). The interface never sends a path to act on: items are opaque IDs of Rust's own scan results, re-checked before any move.
4. **The file system.** Handle-based walks with no-follow opens, identity checks, the same volume only, network mounts skipped, exclusive renames that never overwrite, and quarantine before any delete.
5. **Local data.** Minimal by design (no file contents stored, no credentials or telemetry; Duplicates and Similar Images read contents only to compare them in memory, ADR-019; an image is decoded by macOS's ImageIO, like Quick Look, so a malformed image is handled by the system decoder), owner-only permissions, transactional migrations, and a damaged or newer history makes Kleari refuse to move anything. Malware already running as the user can read what Kleari can; that is outside what an app can defend against, and is disclosed in [SECURITY.md](../SECURITY.md).
6. **The supply chain.** Locked dependencies, `cargo audit`, `pnpm audit`, Dependabot and gitleaks in CI, protected `beta`, `release` and `main` branches with required review and CI, and no signing key in the repository or CI.

## Assets and trust boundaries

Assets: user files, credentials and metadata; user grants; operation approvals; quarantine content; SQLite history/settings; integrity of policy and app updates. Boundaries: UI ↔ typed IPC ↔ Rust policy; app ↔ macOS permissions/filesystem; app ↔ SQLite; app ↔ Docker; app ↔ optional AI provider; app ↔ updater/distribution.

## Threats and required mitigations

| Threat | Required mitigation | Residual risk |
|---|---|---|
| Accidental data loss | Read-only scan, explained preview, explicit approval, backend policy, quarantine first, separate permanent-delete confirmation | User may approve an incorrectly classified item; clear uncertainty and review are essential |
| Path traversal / symlink escape | Validate scope in Rust; traversal must not follow symlinks outside approved roots; fail closed on ambiguity | Filesystem namespace may change concurrently |
| TOCTOU, stale scan or replaced file | Bind preview to identity evidence; revalidate path, identity, permission and policy immediately before operation | Some filesystem identity races may remain; document per operation |
| Permission revocation | Handle access errors and revoked grants explicitly; never broaden access automatically | macOS permission behavior can vary by release |
| Insufficient disk space | Check feasibility, handle partial writes and rollback/record state; never fall through to deletion | Space can change after checking |
| Partial operation / app crash | Durable operation states, idempotency, recovery on startup and visible partial status | Abrupt power loss may leave ambiguous state |
| Restore conflict | Refuse overwrite; report destination conflict and let user decide | User intervention may be required |
| Malicious/malformed filenames | Treat names as untrusted data; safe encoding/rendering, no shell interpolation, bounded input and robust serialization | OS and UI rendering edge cases need testing |
| Untrusted AI output | Advisory only; schema validation and escaping; no command execution or authorization path | Incorrect explanations may mislead; disclose uncertainty/provider |
| Compromised/unexpected integration | Narrow read-only Docker surface; validate responses; timeouts; no mutation permissions | Local integration endpoint can expose sensitive metadata |
| Malicious or oversized launchd plists (System page startup items) | Open each plist with `O_NOFOLLOW` (no check-then-open gap) and `O_NONBLOCK`, and read it only if the opened handle is a regular file; cap size (256 KB) and count (500 per folder); parse with the `plist` crate, not a shell; bound label length; send only label, display name, scope and two statuses; program paths only checked for existence, never sent or logged | A plist's label is attacker-controlled text; it is rendered as text, never as markup |
| Startup-item existence check reaching the network | Read the mount table with `getmntinfo(MNT_NOWAIT)` (no file-system I/O); skip programs on any mount not reported local, or on autofs; walk to the program with directory handles, opening each folder relative to its already-open parent with `O_NOFOLLOW | O_DIRECTORY` (storage's fsdir) and `fstatat(AT_SYMLINK_NOFOLLOW)` for the program, so a folder swapped for a symlink mid-walk fails to open instead of being followed; an unreadable mount table checks nothing | A local folder replaced by a mount between the table read and the walk could still be stat'ed once |
| Quitting the wrong process from the Processes page | Only regular apps of this account outside macOS's own folders (so never Finder, Terminal or other apps that ship with macOS), never Kleari, a background or system process; `canQuit` decided in Rust (`may_quit`) and checked again in the contract and the command; a confirmation dialog first; a token is issued only when the PID is still the sampled process, and the backend keeps it with the row's PID and resolved bundle (symlinks followed through directory handles, opened relative to their open parent with no-follow and `readlinkat`, so a swapped parent can't redirect the walk and Apple apps in `/Applications` that link into `/System/Cryptexes` stay protected; nothing at or below a mount the mount table reports as non-local is touched, and such apps aren't quittable); `quit_app` accepts only a token from the latest list, then in one main-thread step checks identity (start time to the microsecond, owner UID), the AppKit app (regular, running, resolved bundle equal to the recorded one and outside macOS's folders), identity again, then calls `terminate`; the frontend never sends a path; only the polite request (no force quit, no signals); outcomes reported as returned; commands granted in the default capability by the product owner's decision ([ADR-009](adr/ADR-009-process-quit.md)) | The app decides how to respond (it may save, ask or decline); microseconds remain between the last identity read and `terminate`; a network volume mounted over part of an app's path after the mount table is read could still be looked up once while resolving its bundle, as for startup items; quits aren't recorded until a history store exists |
| Running Apple's `/bin/ps` for other accounts' process figures | Absolute path, fixed arguments, no shell, empty environment except `LC_ALL=C`, no input, stderr discarded, 1.5 s limit with kill, output capped at 1 MiB and 20,000 lines, parsed as untrusted text with malformed lines skipped; only fills processes already listed, by PID in the same sample; read-only ([ADR-010](adr/ADR-010-system-ps.md)) | A future macOS could change `ps`; changed lines are skipped and those processes fall back to "no memory value"; a PID reused within the same sample could show another process's figures for one refresh, never affecting an action |
| Developer scan reading more than intended | Search roots, the home folder, Docker's disk-image folder and version-file folders opened from `/` one component at a time with no symlink anywhere on the path, so the mount-table check on the lexical path holds; cache locations then opened from that home (or `/`) handle component by component; projects searched only in the home folder (not Library or the Trash) and folders the user picks in the macOS panel, kept in Rust; `fsdir` handle walks with no-follow opens and identity checks, same volume only (cross-device opens refused); build folders measured through the project's open handle, never reopened by path; `.git/logs/HEAD` reached through `.git` and `logs` on the project's volume; mount table read again before each cache location and each root, nothing under a non-local mount (unreadable mount table: nothing searched), skipped roots reported; names and sizes only, except version files (Xcode `Info.plist`, npm `package.json`) and the last 8 KB of each repository's `.git/logs/HEAD`, all opened without following symlinks and bounded; 8 levels, at most 9 folders open, 500 projects, three parts per folder, hard links counted once; one scan at a time, cancellation checked on every entry | Project and folder names are shown on screen; the mount table is a snapshot: while opening a root, cache base or Docker folder from `/` it is re-read before each component and again after any step onto another volume, but a non-local volume mounted over a component in the instant between that read and the `stat`/open could be looked up once (its root `stat`ed and opened) before the post-open re-read refuses it, and below a root a volume mounted mid-walk could be looked up once before the device check stops the descent; nothing inside such a volume is listed or read; a home folder or added folder reached through a symlink isn't searched (reported as skipped) |
| Docker engine socket (Developer page) | One fixed request, `GET /system/df` over HTTP/1.0, to the user's own engine socket; one 10 s deadline across both sockets, 1 s write limit, a non-blocking connect (pending connects polled, a full backlog retried) and reads checked against the deadline and cancellation every 100 ms on the scan's own thread, not asked at all once the scan is cancelled; sockets, the disk image and the installed checks skipped under a non-local mount, the latter two looked up through handles from `/` with no symlink on the way; 16 MiB cap, only a plain 200 accepted, JSON parsed as untrusted, missing or uncomputed sizes shown as minimums; never any other request, and Kleari never runs a Docker command ([ADR-011](adr/ADR-011-docker-disk-use.md), ADR-005) | Another process listening on that socket could feed misleading numbers to the Docker card; the mount-table checks are a snapshot, so a network volume mounted over a socket's folder just after the check could be reached once by `connect`, which resolves the socket path itself |
| Process details exposing paths | Executable paths and bundles shown on screen only; never stored, logged or sent; dropped when the page closes | Paths can reveal folder names in the home folder |
| Opening System Settings from the UI | One command, four fixed panes in a Rust enum; the frontend cannot pass a URL | macOS decides what the pane shows |
| Cleanup moving the wrong item, or more than approved (ADR-012) | Items only come from Rust's own scans (paths and identities never leave Rust; the frontend has opaque hex IDs); eligibility decided by `cleanup::policy` and the item's place fixed by `within_bounds`; preview re-reads and binds identity and size; approval re-checks every item (identity, size, place, policy with apps running now) and moves nothing if one differs; each move re-checks identity immediately before and after the rename, moving a swapped entry back | Between the last check and the rename a swapped entry could still be moved; it lands in quarantine (restorable), never deleted |
| A move falling through to deletion, or overwriting | The only move is `renameatx_np(RENAME_EXCL)` / `renameat2(RENAME_NOREPLACE)` between folders opened without following symlinks, on the same volume; cross-volume fails (`EXDEV`) and the item stays; nothing is copied then deleted; quarantine names are Kleari's hex IDs | None known for the move itself |
| Restore overwriting, landing elsewhere, or restoring a replacement | Same exclusive rename into the original folder opened from `/` with no symlink on the path; anything at the original place blocks it (`conflict`); a missing folder or changed held item blocks it; what arrived is checked against the recorded identity and a replacement moved straight back, otherwise `unconfirmed` (never recorded as restored without proof); the stored original path must pass the same place rules as a new item of its recorded category (`policy::restorable`) before a restore or Show in Finder uses it, so an edited history can't send an item, or point Finder, elsewhere (`notAllowed`, listed as unverified, state unchanged); a build folder outside the home folder goes back only into a folder the user chose in the folder panel this session (Quarantine's Choose folder… is a restore-only grant, never scanned; the recorded added folder only names which one to ask for, worded as what the record says and left out when broad or a volume's own folder, judged from the path alone so listing never touches a history path that could be on a network volume; editing it can't widen the boundary); launch reconciliation concludes `restored` only from an in-scope original, and runs again under the operation lock after a folder is chosen and whenever Quarantine is listed while nothing runs | The user decides what to do with a conflict; a user who chooses a broad folder allows restores there (a build-folder name, outside never-touch folders, nothing overwritten) |
| Permanent delete reaching outside quarantine, or a replacement | Separate confirmation with acknowledgement; only held, confirmed items, by recorded identity, which the walk checks again itself; a folder emptied only through its handle verified against that identity; a handle walk inside the quarantine folder on its volume, `unlinkat` relative to open folders, symlinks removed as links, never followed; owner write added only to folders inside the item | An item can be left partly deleted on an error; it stays held and is reported. Without unlink-by-handle, a file swapped between its last `lstat` and `unlinkat`, or an empty folder swapped in before the final `rmdir`, could still be removed |
| Losing where an item came from | Batch and items recorded (`moving`) before anything moves, in one transaction; no record, no move; a restore recorded `restoring` first; a move that can't be checked afterwards stays `moving` (`unconfirmed`), never `notMoved`; a kept swapped entry's real identity recorded; `synchronous = FULL`; at launch, records resolved only from what the folders prove (held, absent, back at the original place), kept as they are when the folders can't be inspected | The original path is stored locally (owner-only file) because restore needs it |
| Folder-access prompts or silent broad access | Protected folders read only after Grant access; answers remembered; refusals shown with a link to Files and Folders; Full Disk Access is never assumed, only reported as needed | macOS may change its prompts |
| Storage page analysis reading more than intended | Locations fixed in Rust, never sent by the frontend; `fsdir` handle traversal with no-follow opens and identity checks; no other devices; explicit exclusions so the Data volume and swap aren't walked through `/System/Volumes` or counted twice; cloud folders skipped so listing can't trigger provider downloads; names, sizes and modification times only; the one exception is installed apps' `Info.plist` (no-follow, regular file ≤ 256 KB, ≤ 2,000 bundles, parsed as untrusted), read only on the Applications folder's own volume and never at or below a mount the mount table reports as non-local (the table re-read before each folder and bundle; unreadable stops indexing); bounded tree, lists and hard-link set; one analysis at a time, cancellable, cancelled on unmount | macOS may show privacy prompts for protected folders; firmlinked folders share a device ID, so the exclusion list must stay correct as macOS changes its volume layout; while apps are indexed, a volume mounted between a mount-table check and the next lookup could be looked up once before the device check stops the descent |
| Full Disk Access check | Opens and immediately closes three folders that only Full Disk Access unlocks and that macOS never prompts for; nothing inside is listed or read | The result can change at any time in System Settings; it is re-read each time the page is shown |
| Sensitive paths in logs | Minimize and redact paths; no secrets/content; review crash reports and support bundles | Metadata can remain identifying |
| Database corruption / interrupted migration | Implemented: transactional numbered migrations, `quick_check` on open, newer schemas refused, a damaged file left untouched and every file-changing operation refused until it is resolved; backups/recovery design still open | Local data may be unrecoverable after storage failure |
| Background lifecycle / permissions | Foreground by default; background only after explicit lifecycle/permission and shutdown design. Implemented (ADR-013): System activity and the process list are sampled while Kleari is open to look at, its window visible or its menu-bar popover open (System every 5 s, or 1 s on its page; processes every 5 s, or 2 s on theirs), never while both are out of sight or paused; Open at login goes through macOS Login Items (`SMAppService`), read back from macOS, which shows its own notice; notifications ask macOS once, only when turned on, and are touched only from the app bundle | OS scheduling and grants can change asynchronously; a login item means Kleari opens with the session |
| Activity log and preferences revealing or widening behaviour | Events store counts, sizes, outcome codes and a subject (scan mode, protected folder ID, app name), never paths; item lines join quarantine records and show only a name and `~/…` folder; retention deletes old events at launch and on change, Clear log deletes all; preferences and exclusions are validated against the page's choices in Rust (unknown or out-of-menu values fall back to defaults) and can only leave findings out, never make anything eligible; preview and approval apply the current ones again to freshly read size and modification time, so an item excluded or changed after the scan never moves; Cleanup scans never open excluded folders (checked before any `stat`), the Developer search and cache measurement skip them, and anything that contains an excluded folder is never measured or offered; outside the home folder the log shows only a folder's own name; an excluded folder is removed only by matching Rust's own list | The log and exclusion paths persist locally in the owner-only history file; app names in quit events are identifying metadata |
| Malicious update/dependency | Controlled dependencies, least-privilege CI and release review. Implemented (ADR-014): updates come only from two manifests fixed in Rust (Kleari's GitHub releases over HTTPS: the latest stable release's, or with Beta updates on, the rolling `beta-channel` release's), chosen by a validated preference, never by text from the interface; an update is offered and downloaded only from an HTTPS asset URL of Kleari's own releases on github.com; it is installed only after the user chooses it, only if its minisign signature matches the public key built into the app and names the announced version (`requireSignedVersion`, so an older signed build can't be passed off as newer), and only under the quarantine operation lock, held until the restart; any failure leaves the installed app unchanged. The private key is kept outside the repository and CI | A stolen updater key (with its password) could sign a malicious update; GitHub account compromise could withhold updates. No Apple notarization, by the owner's decision |
| Scheduled scans acting without the user (ADR-015) | Off by default; read-only, the same scan, exclusions and folder grants as a scan the user starts, never asking for folder access; run only while Kleari runs, never during another scan or a quarantine operation, at most once per scheduled time (recorded first); nothing moves without the user's approval of a preview; a notification says what was found | A scheduled scan replaces the review the user may have been working through |
| Mouse module reading or forging input (ADR-016) | Off by default and only after the user allows Accessibility; the event tap asks only for wheel and extra-button events, and left or right click each only while a combination uses it (never keys or pointer movement); left click always reaches apps unchanged; it stores, logs and sends nothing; it posts only the fixed shortcuts or the one the user recorded, in response to the user's own mouse input, tagged so they aren't processed again; a failure passes the event through unchanged; settings validated in Rust | Accessibility is a broad grant held by Kleari's signature; a stalled tap delays wheel and button events until macOS disables it |
| Menu-bar popover widening access (ADR-014) | Its own capability: only the reads it shows, `open_main` (a fixed destination enum, so no script or route text reaches the main window), `hide_popover` and `quit_kleari`; no scan, move, delete or settings command; it reads nothing while closed | Shows the same summary data as the Dashboard to anyone at the unlocked Mac |
| Uninstall removing the user's files (ADR-014) | Runs only from an installed `.app`, under the quarantine operation lock, and only while quarantine is empty (unreadable counts as not empty); moves to the Trash (never deletes) only Kleari's fixed `~/Library` locations for `dev.bakare.kleari` and its own bundle, last; reports anything it couldn't check or move, and an Open at login macOS kept on | macOS permissions remain until the user runs `tccutil reset`; WebKit may recreate its storage folder as the app quits |

## Security invariants

Scanning is read-only. Ambiguous or protected paths fail closed. Quarantine failure never deletes permanently. Restore never overwrites. Docker is read-only. No root daemon, broad permissions, default telemetry or content upload. Synthetic fixtures only; never test against personal files or persistent Docker volumes.
